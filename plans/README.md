## Findings considered and rejected

- **Wholesale shadcn restyling**: rejected. The custom sand, ink, crimson, dense-row, panel, and course systems are already coherent and are part of the approved BASidekick direction.
- **Replacing every form control with a shadcn component**: rejected. Native inputs are adequate here; dependency and migration cost would exceed the accessibility gain.
- **Splitting `components/app-shell.tsx` only because it is 317 lines**: rejected. File length alone is not a defect; extract only the overlay and sheet behavior while implementing plan 002.
- **Skeletons on every route**: rejected. Most public pages have useful curated fallbacks and server-render quickly. Loading work should stay targeted until real latency data identifies a problem.
- **Force-overriding Next.js transitive PostCSS and Sharp versions**: rejected for now. `next@16.2.12` is current and pins those packages; an unsupported override could destabilize image/build behavior. Recheck after an upstream Next release.
