# Animation Improvement Plans

Generated by the Improve Animations and Emil design-engineering review on 2026-07-25. The application is a crisp, utility-first workspace; motion should confirm state or explain course content, not decorate routine navigation.

## Recommended execution order

| Plan | Title | Severity | Status | Dependency |
|---|---|---:|---|---|
| 001 | Make command search immediate | HIGH | DONE | Executed before the accessible primitive migration |
| 002 | Make button press feedback win | MEDIUM | DONE | None |
| 003 | Give course target markers physical entrances | MEDIUM | DONE | None |
| 004 | Restrict geometric hover motion to precise pointers | MEDIUM | DONE | Executed after 002 |

Status values: TODO, IN PROGRESS, DONE, BLOCKED, or REJECTED.

## Audit disposition

- Keep the landing hero and preview entrances: they are rare, under 700ms, use transform-only motion, and honor reduced motion.
- Keep interactive course transitions: they explain state changes and preserve the original learning interactions.
- Keep the animated sidebar icons: this is an explicit, settled BASidekick design choice. Do not expand their 520ms click playback to other controls.
- Keep the global duration scale (`120/180/280ms`) and strong existing easing tokens. A parallel token system would reduce cohesion.
- No `transition: all` or UI `ease-in` usage was found.
- Reduced motion is already handled globally and through `MotionConfig reducedMotion="user"`.

## Missed opportunities intentionally deferred

- A subtle first-success treatment for a user’s first PointStack contribution could use the rare-event delight budget, but no complete first-submission workflow exists yet.
- Toast motion is not planned because the app does not yet have a canonical toast system; adding one solely for animation would be speculative.
